# 成长记录

「成长记录」按直播间保存粉丝牌每日亲密度涨幅，展示今日与近 7 日。页面只呈现一个账号的历史，不跨账号合并。

## 数据口径

- 数值来自 `get_my_medals` 的 `today_intimacy`（缺少时退回 `today_feed`），按 UTC+8 自然日归属，服务端每日 00:00 重置。
- 同一天多次探测取最大值。探测成功但当天没有新增时记录 `0`；`0` 是有效记录，不等于「未记录」。
- 没有探测或查询失败不建当天房间键：过去的日子显示「未记录」，今天尚未产生采样时显示「尚未同步」。当前关注但还没有粉丝牌数据的直播间也暂时显示「尚未同步」，待后续版本区分「无粉丝牌」。两者都不补 0，也不参与合计。
- 采样时间使用读取粉丝牌时的 `medals_at`，不是整次探测结束时间，避免任务查询跨过午夜后把深夜样本记到次日。
- 历史从本版本开始记录。旧版本没有每日快照，活动日志的会话窗口不足以还原当日总量，因此不回填。

## 文件

每个账号保存在自己的数据根：

```
<account root>/state/growth.json
```

结构（`SCHEMA_VERSION = 1`）：

```json
{
  "version": 1,
  "account_id": "uid-123",
  "updated": 1794039120.5,
  "days": {
    "2026-11-07": {
      "samples": 12,
      "first_at": 1794030000.0,
      "last_at": 1794039120.5,
      "rooms": {
        "22637261": {
          "uid": 672328094,
          "name": "嘉然今天吃什么",
          "medal_name": "小草莓",
          "level": 9,
          "max": 420,
          "last_value": 420,
          "samples": 3,
          "first_at": 1794032100.0,
          "last_at": 1794039120.5
        }
      }
    }
  }
}
```

- 写入使用既有的 `update_json` 原子替换与文件锁；损坏、版本未知或 `account_id` 不匹配时失败关闭，历史原样保留，并在日志中记录 `Cannot record fan-medal growth`。
- 保留 90 天，更早的日期在成功写入时裁剪。
- 早于该房间最新记录日期的样本会被拒绝，防止系统时钟回拨改写历史；未来日期同样拒绝。
- 房间元数据随样本更新；当前关注列表里的名称优先于历史名称。已移除的主播保留历史行，标记 `tracked=false`，显示在「已移除」分组。
- 移除账号时 `state/growth.json` 随关注、设置、任务与额度一起移入 `accounts/.retained/<id>/`；重新添加同一 UID 时恢复。

## 写入路径

`AppContext.probe` 读取粉丝牌后记录 `medals_at`，`Engine._apply_probe` 在探测成功后调用 `bilioshi.growth.record_samples`。任何 IO、结构或时钟异常只写 WARNING，不阻塞探测与挂机。

## 桥接接口

`Api.growth(days=7, account_id=None)`，不进入 0.75 秒一次的 `snapshot`：

- `days` 为 1–90 的整数；`account_id` 省略时使用当前查看账号，`all` 视图回退到活动账号，再回退到注册表第一个账号。未知账号返回稳定的 `available=false`，不静默读取其他账号。
- 返回 `available`、`error`、`today`、`days[]`、`rooms[]`、`coverage{}`、`account_id`、`account_name`、`running`、`paused`、`status`。
- `rooms[].cells[]` 与 `days[]` 一一对齐；`recorded=false, value=null` 表示没有采样。`rooms[].tracked=false` 表示已移除主播。
- `coverage[day]` 给出采样数、首末时间、当前关注房间的已记录/可记录数与是否不完整。今天的 `partial` 始终为真。
- 结果按 `(账号, 天数, UTC+8 日期, growth.json 修改时间/大小, members.json 修改时间/大小)` 做单条缓存；文件变化、切换账号或跨过午夜立即失效。签名与返回数据共用同一个时间戳，避免午夜边界上的缓存错位。

## 界面

侧栏「成长记录」页：

- 一行元信息与账号标签；两张摘要卡（今日成长、近 7 日）；每日总成长柱状图；各直播间单行列表（名称、7 日微柱、今日、合计）。
- 点击直播间把柱状图切换为该房间的近 7 日序列，可「查看全部」返回。
- 今天标「进行中」；账号未挂机时标「未挂机」，并在顶部说明数据停在何时。登录失效或保护暂停的历史仍可查看，入口指向账号页。
- 页面每 60 秒静默刷新；切换查看账号、账号列表变化或重新进入页面时重新读取。请求带代次校验，旧响应不会覆盖新账号。
- 未记录、尚未同步、0 与已移除分别用文字、虚线空槽和分组区分，不只依赖颜色；数字使用等宽数字。

## 边界

- 第一期一次只展示一个账号，同一房间被两个账号关注时是两条独立序列。
- 不做跨账号合计、CSV/图片导出、旧活动日志回填、历史周报或手机端。
- 当前关注列表中的房间都计入覆盖分母；尚未拿到粉丝牌的直播间也会暂时显示为「尚未同步」，待后续版本区分「无粉丝牌」。
- 升级前没有 `growth.json`，历史从升级后的第一次成功探测开始；账号迁移不搬运旧成长文件。
