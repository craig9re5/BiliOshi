# ビリ推し 多账号交互设计稿

## 目标

在三件事之间建立清楚的分工：

1. **切换查看**：只改变当前看到的总览，不改变哪些账号在运行。
2. **切换运行**：单账号模式下切换账号会停止旧账号、启动新账号；同时挂机模式下由每个账号的开关决定。
3. **账号数据**：关注列表、任务进度、今日额度、登录凭证都按账号隔离；切换不需要重新扫码。

设计稿复用生产界面的表面语言：纸白 `#fcfcfb`、白色卡片、细线描边、深青 `#2d6763` 只用于操作与状态。没有引入新的装饰色。

## 预览

直接打开 `Multi-Account.html`，或在仓库根目录启动：

```bash
python -m http.server 4311 --directory designs
```

然后访问 `http://localhost:4311/multi-account/Multi-Account.html`。

顶部的“单账号运行 / 同时挂机”是评审开关，用来对比两种模式；右侧“账号切换器 / 添加账号”可以直接打开对应弹出层。

| 侧栏切换器 | 快速切换查看；显示每个账号的挂机状态、登录失效、当前查看勾选；底部进入管理页或添加账号 |

## 关键设计决策

### 账号标签 vs 上下文字段

采用“全部 + 每个账号”的横向标签，而不是只在总览顶部放一个下拉字段。原因：

- 3–5 个账号时，标签能同时显示名称、运行状态点和直播数，一眼能看出哪个账号在挂机。
- 每个标签就是一个独立的直播总览，符合“针对每个账号独立显示”的要求。
- 账号数超过 5 时标签横向滚动；这与方案中的账号上限一致。

### 查看 ≠ 运行

- **顶部标签只切查看**：点击任何账号标签都不会停止或启动连接；未运行账号显示上次快照并标注“上次运行 X 前”。
- **单账号模式**：侧栏切换器是“切换挂机账号”，账号页的“切换并挂机”才会停止旧账号、启动新账号；这是显式动作，且不扫码。
- **同时挂机模式**：切换只改查看；每个账号在管理页有独立的“同时挂机”开关。
- 侧栏和标签始终同时表达两种信息：状态点（运行中/未运行/失效）和当前查看勾选；查看与挂机不同时，侧栏显示“查看：X / 挂机：Y”。

### 非活动账号显示陈旧数据，但不伪装实时

未运行账号的详情显示“上次运行 X 前”，并给出中性横幅；操作按钮禁用或改为“开始挂机 / 切换到此账号”。这比显示空白更利于判断，也比把旧数据当成实时安全。

### 三种暂停分开表达

- **账号暂停**：用户对单个账号点“暂停此账号”，保留数据，手动恢复。
- **全局暂停**：“全部暂停”是应用级覆盖层，不改写每个账号自己的暂停状态；恢复时只恢复暂停前正在运行的账号，单独暂停的账号保持暂停。
- **保护暂停**：由平台验证或异常拒绝触发，显示原因与处理入口，重新扫码、重启、重新添加都不会解除；应用内不能跳过。
- “参与同时挂机”是第四种状态：它决定账号是否属于并发运行集合，但不会修改暂停；暂停中的账号可以保持参与，只是不运行。

### 退出登录与移除账号分开

- **退出登录**：停止该账号连接、删除本机凭证，保留账号行、关注、任务进度、额度与保护记录；状态变为“登录失效”，重新扫码即可恢复。适合暂时不用某个账号。
- **移除账号**：移出账号列表，并把关注、设置、任务额度、保护记录转移到 `.retained/<uid>/`；普通界面不提供清除额度或保护记录的入口，避免通过“移除再添加”重置每日上限。
- 退出当前运行账号后不自动启动其他账号；不会把“退出”做成隐式的“切换”。

### 对话框与焦点

切换、关闭同时挂机、退出登录、移除、风险确认、退出应用都使用确认对话框。对话框打开后聚焦对话框本身，Tab 焦点限制在内部，Escape 关闭；关闭后焦点回到触发按钮，若该按钮已被重新渲染则回到账号切换器。切换查看与切换运行不会因为键盘操作而混淆。

### 设置作用域可见

挂机设置顶部固定显示“应用对象：账号名”；外观主题标注“全应用，不随账号切换”。服务端负责状态与主操作，React 只渲染，避免 Web/Tk/第二期多 Engine 三套规则分叉。

## 尚未覆盖

- 真实二维码由登录接口生成；设计稿用演示二维码占位。
- 同时挂机的资源上限、跨账号限速和全局保护暂停属于第二期方案；设计稿已包含风险确认弹窗、逐账号参与开关与全局暂停，第一期实现时先隐藏“同时挂机”分组。
- Tk 兼容界面未做多账号设计；方案建议 Tk 只显示当前账号。
