# 手机每日总结 · 使用与验收

当前灰度版本：**未启用，所有 UI 入口隐藏**。即使保留旧的启用配置，桌面调度与发送出口也不会发送通知；CLI 的配置、测试、运行和恢复入口被阻止。只读状态与预览保留用于开发。

下文是未来开放后的使用与验收草案，当前版本无法按这些步骤启用。手机通知原型范围只有每日总结。

## 你需要补全的步骤

1. 使用新版 BiliOshi，打开「自动化设置」，向下滚动到「手机每日总结 · QQ」。
2. 登录 PushPlus 并完成实名，在 [QQ 渠道配置说明](https://www.pushplus.plus/doc/channel/qq.html) 对应入口扫码添加和绑定机器人。
3. 创建一个 BiliOshi 专用的**消息 Token**，粘贴到软件本地密码框。留空保留已保存值；凭证不回显。不要把 Token 或 B 站 Cookie 发到对话、截图或 GitHub。
4. 先保持自动发送关闭，点击「保存每日总结」，再点击「发送测试消息」并确认。测试只发合成日报，不操作 B 站账号。稍候在软件状态与手机 QQ 检查结果。
5. 确认手机 QQ 允许通知、机器人会话没有免打扰，再打开「每天发送一条收益总结」并保存。默认 UTC+8 每日 **23:50**，可调整时间。

实名非会员的 QQ 消息仅显示标题摘要；完整正文可到 PushPlus 消息记录查看。会员的正文展示能力以渠道文档及实机结果为准。软件使用 QQ 机器人私聊本人，不要求群号、开放接口 secretKey 或额外 B 站 Cookie。

## 消息内容与收益口径

标题示例（合成数据）：`10-12日报｜已核验+39｜6/7房 待核验`。

正文列出观测日期、截至时间、已核验合计、各关注主播当天亲密度、弹幕/点赞/看播/灯牌进度及仍在播标记。

- 亲密度来自本次完整粉丝牌查询的 `today_intimacy`（底层 `today_feed`），不使用等级经验或心跳次数推算。
- 合计只加有效的非负整数计数。同一粉丝牌重复配置只计一次。
- 未获取、查询失败、过期、跨日的值标为「待核验」，不填零，不沿用昨日缓存。
- 这是服务端当天累计，可能包含手动和其他工具获得的收益；并非本软件运行的净增量。
- 日报是截至发送时的快照。23:50 后仍在播的房间可能继续增长；软件不承诺最终全天结算值。
- 只发送已保存配置；修改隐藏名称等选项后应先保存，再预览。

## 调度与可靠性

通知默认关闭。开启后，独立后台线程每 15 秒检查发送时间，到点作一次只读收益核验并发送。当日错过时间后重新打开软件，会在午夜前补发当天总结；跨日不追发昨天，避免用新日期计数拼凑旧日报。

关闭主窗口保留托盘时继续工作。暂停挂机不等于关闭每日总结；账号保护暂停会遵守现有只读查询保护，并在日报中标注无法核验。电脑退出、断电或跨日才恢复联网时，无法保证补发。此版不接入主机离线告警。

SQLite 保存发送状态和本机预算。同账号同日期只生成一条自动日报；多个房间、多次启动或多进程不会重复发送。清空待发、恢复通道不清除每日防重记录和额度。更换 Token 或账号会取消旧的待发消息；不会把旧账号的收益发给新配置。

消息在当天午夜过期，测试消息 10 分钟过期。每次请求消耗一次本机发送尝试，间隔至少 30 秒，本机每日上限 100 次；其他软件也可能消耗同一 PushPlus 账号额度。

只有明确的 DNS 域名解析失败允许重试，最多共三次，等待 60 秒、300 秒。超时、断连、无效响应、HTTP 异常或提交中断一律标为结果未知，不重放可能已被接收的请求。

服务业务拒绝会持久化暂停通知通道，软件显示固定的脱敏原因。处理实名、Token、绑定或额度后点击「恢复通知通道」；已失败、已受理或结果未知的旧日报不会重发，次日恢复自动发送，可用合成测试验证新配置。

`服务已受理` 表示 PushPlus 返回业务成功和流水号，不代表手机弹窗或已读。此版不存开放接口高权限凭证，不自动查询最终投递结果；去 PushPlus 消息记录查看并用手机验收。

## 本机配置与隐私

普通设置位于 `settings.json` 的 `daily_notification`：

```json
{
  "daily_notification": {
    "enabled": false,
    "summary_at": "23:50",
    "anonymous": false
  }
}
```

Token 单独保存在 `pushplus.credentials.json`，Windows 使用用户级 DPAPI，其他平台使用现有安全系统凭据库；不回退明文。删除 Token 会关闭自动通知。队列位于 `state/notifications.sqlite3`，不包含登录凭证，消息正文超过七天清空；历史防重键继续保留。

正文通过 PushPlus 和 QQ。可选择隐藏主播名称；不发送个人账号昵称/UID、设备标识、路径、Cookie、完整 API 响应或错误堆栈。队列和凭证列入 Git 忽略及公开文件检查。发送器固定 HTTPS 目的地并拒绝重定向，不复用 B 站客户端的 Cookie 或认证头。

设置保存后自动生效。正在提交的请求无法撤销；关闭/删 Token 会阻止后续新请求，但不能撤回供应商已经接收的消息。退出软件会等待正在执行的只读查询或发送结束，避免把它误报为尚未提交。

## CLI（与桌面使用同一服务）

在已配置项目环境中：

```powershell
python -m bilioshi.notifications --status
python -m bilioshi.notifications --preview
python -m bilioshi.notifications --configure
python -m bilioshi.notifications --test
python -m bilioshi.notifications --run
python -m bilioshi.notifications --resume
```

`--configure` 使用隐藏输入，不把 Token 放进命令参数；`--preview` 只读查询；`--test` 明确发送一条合成消息；`--run` 是常驻调度器。已安装 Python 包还可使用 `bilioshi-mobile-summary`。桌面不需要同时运行 CLI。
