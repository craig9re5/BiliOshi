# ビリ推し 成长记录页设计稿

## 目标

把每天各直播间的粉丝牌成长值记下来，用一页看清「今天涨了多少、近 7 日怎么走、每间房分别怎样」。

- 新增独立侧栏页「成长记录」，不改动直播总览的列表与详情排布。
- 只读展示，不触发任何 B 站接口，不上传数据。
- 今日是部分数据，界面必须标注截至时间；没有记录的日子显示「未记录」，不补 0。
- 本稿只新增 `designs/growth-tracking/` 下的设计文件，**没有修改生产代码**；审批后再按「实施清单」落地。

## 口径与边界

**成长值 = 粉丝牌今日亲密度。**

- 服务端字段：`get_my_medals()` 返回的 `today_intimacy`（部分响应为 `today_feed`）。
- UTC+8 每日 0 点重置，项目内统一用 `bilioshi/runtime.py:task_day()`。
- 不是等级经验累计值（`intimacy` / `next_intimacy`），也不是本轮挂机净增量。
- 它是该登录账号的当日累计，可能包含手机、网页端、手动弹幕等收益；页面措辞为「账号当日亲密度观测值」，不宣称为本软件独占增量。

**每日涨幅 = 当天观测到的最大值（max），不是最后一次值。**

服务端计数当天单调累计、次日清零，`max` 就是「截至最后一次观测的当日总量」。它不受重复探测、短暂回退和乱序影响；如果当天 22:00 才启动，第一次读到 300，`max=300` 就是正确的当日总量，不是「启动后涨了 300」。

**0 与「未记录」严格分开。**

| 情况 | 存储 | 界面 |
| --- | --- | --- |
| 有勋章、当天至少一次有效观测为 0 | `recorded=true, value=0, samples>=1` | 显示「0」，柱图 2px 基座 |
| 没有运行 / 查询失败 / 勋章缺失 / 保护暂停 / 没有采样 | 不建房间或日期键，`recorded=false, value=null` | 显示「未记录」，不参与合计 |

**历史从新版本开始记录。** 旧版本没有每日成长文件，过去的日子不补记、不按 0 计算；活动日志的 `watch_end` / `intimacy_delta` 只覆盖会话窗口，跨午夜会返回 `null`，不能当作当日总量，因此**不做自动回填**。

**覆盖分母 = 有已确认粉丝牌的房间。** 没有粉丝牌的房间不计入「已记录 / 可记录」的分母，也不参与任何合计，只在明细里单列「无粉丝牌」；「未点亮」不是「无粉丝牌」，不排除出合计。成长值按粉丝牌归属，页面按直播间展示：历史行使用当日保存的名称与房间号，主播换房间号时旧历史保留、新房间从零开始，不自动合并。

## 数据采集与存储

### 采样落点

唯一写入点是 `desktop/engine.py` 的 `Engine._apply_probe`：

```text
desktop/engine.py:549  _apply_probe
  ... 已排除 suspended、过期探测、无 statuses 的失败结果
  :583  if "medals" in result and isinstance(result["medals"], dict):
  :584      self.medals = result["medals"]
  +         record_growth_samples(self, result, now)   # 新增
  :585  if "tasks" in result ...
```

选择这里的理由：

- 只有本次探测确实带回 `medals` 才会进入，查询失败、账号保护、暂停、退出都到不了这一行。
- 能同时拿到 `self.members` 的 room ↔ uid 映射与本次勋章值，不会把旧值写成 0。
- 不会在 0.75 秒一次的快照路径里写历史。

建议在 `bilioshi/application.py` 的 `probe()` 中，`get_my_medals()` 返回后补一个 `medals_at = time.time()` 放进结果，作为日期归属时间；没有该字段时退化为 `probe_started`（探测开始时刻），不要用整轮探测结束或写盘时刻，避免任务查询跨午夜把值记到错误日期。

### 文件与结构

每个账号一个文件，天然隔离：

```text
<install_root>/accounts/uid-<mid>/state/growth.json    # 多账号
<install_root>/state/growth.json                        # legacy 单根模式
```

```json
{
  "version": 1,
  "account_id": "uid-1891335475",
  "updated": 1762500300.0,
  "days": {
    "2026-11-07": {
      "samples": 8,
      "first_at": 1762470000.0,
      "last_at": 1762500000.0,
      "rooms": {
        "22637261": {
          "uid": 1891335475,
          "name": "嘉然今天吃什么",
          "medal_name": "小草莓",
          "level": 9,
          "day_limit": 1500,
          "max": 420,
          "samples": 8,
          "first_at": 1762470000.0,
          "last_at": 1762500000.0,
          "last_value": 420
        }
      }
    }
  }
}
```

约定：

- `version: 1`；未知版本按不可用失败关闭，不覆盖、不降级。
- `account_id` 与账号根核对，不一致视为不可用，防止把别的账号文件当成本账号。
- `days` 键为 UTC+8 的 `YYYY-MM-DD`；保留 90 天（含今天），每次成功写入后裁掉更早的键。
- `rooms` 键为直播间号字符串；`uid`、`name`、`medal_name`、`level`、`day_limit` 保存最近一次有效采样的元数据，空值不覆盖已有非空值。
- `max` 是展示值；`last_value` 只用于诊断。
- 不写 `null` 充当 0；有效 0 必须保留为 `max=0, samples>=1`。

### 采样规则

1. 每次成功探测批量处理所有成员，不挂在 `cycle` / `tick` / `snapshot` / worker 上；采样粒度等于探测间隔（稳健 5 分钟、激进 1 分钟）。
2. 只使用本次 `result["medals"]`，不读 `self.medals` 或 `status.json` 的旧值。
3. 按 uid 取勋章（兼容 int / str 键）；`member` 的 uid 去重。
4. 只接受 `type(value) is int and 0 <= value <= 上限`；`None`、`bool`、负数、字符串、缺失键一律跳过，不写 0。
5. 合并：`max = max(existing.max, value)`、`samples += 1`、更新 `last_value/last_at`；`max` 合并天然幂等。
6. 日期护栏：拒绝早于该房间已记录最新日期的样本（时钟回拨），拒绝晚于 `task_day()` 的样本（时钟前跳）；同一天内回拨由 `max` 吸收。
7. 写入用 `bilioshi/runtime.py:update_json`（`FileLock` + `mkstemp` + `os.replace`），一次探测一次原子写；无变化可跳过写盘。
8. 写入异常（`OSError`、`TimeoutError`、`ValueError`、磁盘满、被杀毒软件占用）只记日志并跳过本次，绝不让异常穿透 `_apply_probe`；下一次成功探测用 `max` 自动追赶。
9. 文件损坏（非法 JSON、未知版本、字段类型错误）时采样器跳过写入，绝不覆盖；API 返回 `available=false` 和错误文案。
10. 文件超过约 4 MB 时停止新增房间并记日志，继续更新已有房间；单房间 `max` 设合理上限（例如 10,000,000）防止异常响应污染。

### 不写入的场景

安全保护、`suspended`、退出/关闭、探测无 `statuses`、`get_my_medals` 抛异常、探测超时被 kill、通知线程的独立只读探测——都不能产生 0 样本，文件应保持原样。

暂停中手动 `check_now` 若探测成功，允许写入真实观测值；如果产品要求暂停期间不计入，需在采样入口显式判断并写进验收。

## 桥接端点

新增 `Api.growth(days=7, account_id=None)`，**不放进 snapshot**（快照每 0.75 秒推送，不能塞 90 天历史）：

```json
{
  "schema": 1,
  "generated_at": 1762500300.0,
  "today": "2026-11-07",
  "days": ["2026-11-01", "2026-11-02", "2026-11-03", "2026-11-04", "2026-11-05", "2026-11-06", "2026-11-07"],
  "rooms": [
    {
      "room": 22637261,
      "uid": 1891335475,
      "name": "嘉然今天吃什么",
      "medal_name": "小草莓",
      "level": 9,
      "tracked": true,
      "recorded_days": 6,
      "recorded_total": 1885,
      "cells": [
        {"day": "2026-11-01", "recorded": true, "value": 310, "samples": 72, "last_at": 1762000000.0},
        {"day": "2026-11-03", "recorded": false, "value": null, "samples": 0, "last_at": null}
      ]
    }
  ],
  "coverage": {
    "2026-11-07": {"samples": 8, "first_at": 1762470000.0, "last_at": 1762500000.0,
                   "rooms_recorded": 6, "rooms_recordable": 7, "partial": true}
  },
  "available": true,
  "error": ""
}
```

- `days` 升序、长度恰好为 `days`，最后一天是当前 UTC+8 日期；每个房间的 `cells` 与 `days` 一一对齐。
- `recorded=false / value=null` = 未记录；`true / 0` = 有记录且为 0；`true / 正整数` = 当天最大值。
- `recorded_total` 只对请求窗口内「已记录」的日期求和，是下界，字段名避免叫 `total`。
- `partial` = 日期是今天，或最后有效采样早于该日 23:55（UTC+8）。
- `rooms_recorded` / `rooms_recordable` 的比值就是界面上的「6/7 间」；无粉丝牌房间只出现在 `rooms` 行里并带 `medal_state: "none"`，不进入分母。
- 读取目标账号的 `state/growth.json` + `members.json`，不读运行中 Engine 的 `self.medals` 或 `last-snapshot.json`。
- 当前关注但从未记录的房间也要返回，`cells` 全部 `recorded=false`，让界面显示「未记录」而不是缺行。
- 已移除主播只从 `growth.json` 出现，`tracked=false`，名称用历史 `name`。
- 文件缺失不是错误：`available=true`、所有 cells `recorded=false`；文件损坏才是 `available=false`。
- `_sync_active()` 时清空成长缓存；缓存签名包含该账号 `growth.json` 与 `members.json` 的 `(mtime_ns, size)`。
- `account_id=None` 用当前 view 账号；未知账号返回稳定错误，不走 `_account_root` 的静默回退。
- 第一版一次只呈现一个账号，不做跨账号合计；同一房间被两个账号关注时是两条独立序列，绝不把 `today_intimacy` 相加或覆盖。

## 两个界面方向

设计稿顶部可切换；两者复用同一份合成数据（7 个直播间、7 天、1 个整天未记录、1 个房间今日未记录、多个 0）。

### 方向 A · 看板型（推荐）

一条自上而下的阅读顺序：**摘要 → 近 7 日趋势 → 各直播间明细**，没有模式切换。

- 摘要：只留两张卡，今日成长与近 7 日；覆盖信息放到图表和明细里，不重复。
- 趋势：7 根单色柱，零基线；今天实色并标「进行中」，过去日浅青；未记录日画虚线空槽；0 画 2px 基座；只在不完整的日子下标覆盖比例（如 6/7）。
- 明细：每行「头像 + 名称」「7 日微柱」「今日」「合计」；点击一行把趋势切成该房间的 7 日序列，可「查看全部」返回。
- 未记录房间排在已记录行之后，用 1px 分隔线 + 「今日未记录 · 1 间」分组。
- 不在界面重复解释口径：数据口径、0/未记录的差异和「含其他客户端收益」放在悬停提示与 README 里，页面上只保留必要文字。

推荐理由：

1. **需求覆盖最完整**：一屏同时给出「今日 / 近 7 日 × 各直播间」，不需要来回切换。
2. **阅读顺序稳定**：今日在摘要、趋势末柱、明细今日列三处重复，形成同一条深青线索。
3. **图表语义正确**：单系列每日总量、零基线、不插值、不累计，正好对应每天重置的 `today_intimacy`。
4. **视觉安静**：全页只有一个 26px 数字层级，其余递减；单色深青 + 纸白，不引入新的彩色家族。
5. **实现最轻**：CSS grid + CSS 柱，无图表库、无新依赖、无 CSP 变更。

### 方向 B · 榜单型（备选）

以「今天谁涨得最多」为主角，今日是排行，近 7 日切到「总柱图 + 矩阵表」。

- 今日：3 个摘要 + 排行（名次、头像、名称、横向条、今日值）。
- 近 7 日：总柱图 + 各直播间 × 7 日矩阵，按 7 日合计排序。
- 0 保留 2px 基座，未记录用虚线轨道 + 「未记录」。

它的优点是把「今天谁第一」做得最快，也复用了总览的「列表 + 详情」心智；不足是核心问题被拆成两次查看，7 日模式里今日每间房的数值消失，榜单的比较语气也容易把「陪伴记录」变成「业绩排名」。因此作为备选，不作为默认。

## 状态矩阵

| 状态 | 表现 |
| --- | --- |
| 0（有记录） | 显示「0」+ 2px 基座；不等于未记录，照常参与合计 |
| 未记录（没有采样） | 显示「未记录」/「—」+ 虚线空槽；不参与合计，不补 0 |
| 今日尚未同步 | 今天列「尚未同步」，摘要「—」；同步后原位更新，不弹 toast |
| 账号未挂机 | 内容顶部 neutral banner「此账号当前未挂机，数据停在 11/06 21:40。恢复挂机后继续记录」；as-of 改「上次记录」；今日列「尚未同步」；历史照常 |
| 已暂停 / 全局暂停 | 同上，banner 写明「已暂停」；暂停期间不产生样本，也不写 0 |
| 登录失效 / 保护暂停 | 历史仍显示；banner 指向重新扫码或解除保护；今日「尚未同步」 |
| 最近检查失败 | 保留上次成功数据；行内「最近检查失败，显示 11/06 21:40」；不补 0 |
| 读取失败（文件损坏） | `available=false`；错误卡 +「立即重试」+「打开日志目录」；不画 0 基线 |
| 无粉丝牌 | 行内「无粉丝牌」，不参与合计与覆盖分母；不是「未记录」 |
| 尚未开始记录（首日） | 单张引导卡「成长记录从本版本开始，今天首次同步后出现」；不铺 7×N 空表 |
| 记录至 12:03 | 当天只运行到中午；行/摘要写「记录至 12:03」；不声称全天 |
| 房间改名 / 换房间号 | 新日期用新名，旧日期保留旧名；换房间号时旧历史保留，新房间从零开始 |
| 跨日 / 时钟回拨 | 窗口与 today 由 UTC+8 `task_day()` 计算；00:00 后自动变新窗口；拒绝早于最新日期或晚于今天的样本 |
| 多账号 | 一次只呈现一个账号；同一房间两个账号是两条独立序列，绝不合并；账号移除时把 `state/growth.json` 加入保留清单 |

0 / 未记录 / 尚未同步 / 无粉丝牌必须同时用文字、形状和位置区分，不只靠颜色；今天的柱与日期都必须有「进行中」文字，不能只靠实色；所有数字 `tabular-nums`；图表容器给随数据更新的 `aria-label`，或提供一份视觉隐藏的 7 × N 表格（两者只留一份，避免读屏重复）；只给一条汇总状态 `aria-live="polite"`，自动刷新静默，手动刷新/错误才播报。

| 宽度 | 行为 |
| --- | --- |
| ≥ 1100 | 侧栏 224；完整表格（名称 / 196 微柱 / 今日 / 合计） |
| 980–1100 | 侧栏 190；内容约 742；微柱列收至 150，今日/合计 62/64；图表柱 30px |
| 940–980 | 隐藏行内微柱列，保留名称 / 今日 / 合计；7 日趋势由上方图表承担；列头同步隐藏 |
| ≤ 720 | 侧栏折叠为 60（沿用现有）；页面 padding 12；摘要三等分改为单列；表格允许横向滚动并固定首列与今日列 |

真实最小窗口是 980 × 620；1366 × 768 @125% 约 1052 × 534，@150% 约 877 × 445，验收需覆盖这些尺寸与 100/125/150/200% 缩放。卡片用 `min-height` 而不是固定高度，允许页面纵向滚动，不能压缩行高。

### 无障碍

- 页头账号范围用 `role="group" aria-label="账号范围"`；日期范围用 `aria-label="成长值范围"`。
- 趋势柱不抢键盘焦点：给图表容器一个可聚焦的 `role="group"` 与摘要 `aria-label`，柱本身 `aria-hidden`；完整数据由下方明细行按钮提供。若坚持逐柱可聚焦，就不能同时 `aria-hidden`，且每根柱必须有「日期 / 状态 / 数值」的可读名称。
- 明细行是真正的 `<button>`，Enter 选中、Space 选中，方向键在行间移动；选中态用 `aria-pressed`。需要「打开直播间」时放在行末菜单，不依赖双击。
- 焦点环沿用全局 `button:focus-visible` 的 2px 深青外框；卡片 `overflow:hidden` 时改用 inset 描边，避免被裁掉。
- 「今天」除实色外必须有「今天 / 进行中」文字；未记录除虚线外必须有「未记录」文字；0 除基座外必须有「0」文字。
- 自动刷新不播报；手动刷新/错误用一条 `role="status"`。所有日期、星期、as-of 用 `Asia/Shanghai` 格式化；机器时区不是 UTC+8 时写「北京时间 14:32」。

## 风险与未覆盖

- **采样下界**：只有桌面在运行时才有样本；当天晚启动、休眠、查询失败都会让 `max` 低于真实全天值，界面用「截至」和图表覆盖比例表达，不声称完整。
- **其他客户端收益**：`today_intimacy` 可能包含手机/网页端收益；页面写「账号当日亲密度观测值」，不写「本软件收益」。
- **勋章查询全有或全无**：分页任一页失败会导致整轮没有 `medals`，所有房间当天都缺样本；这是比写 0 更安全的选择。
- **账号移除**：当前 `remove` 会 `rmtree` 账号根；若不把 `growth.json` 加入保留清单，移除再添加会丢历史。建议加入保留，或在确认框中明确提示。
- **旧数据迁移**：`account_migration.py` 不搬运 `growth.json`；升级后历史从零开始，发布说明需写清。
- **90 天文件重写**：每次成功探测全量读改写；建议无变化不写、设置文件大小护栏，避免机械盘/同步目录放大 IO。
- **本轮不做**：跨账号合并总览、CSV/图片导出、手机端、周步进/历史周报、活动日志回填。这些都需要单独审批。
